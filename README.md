# AI-gent

面向个人用户的本地 AI 协作工作台。用户只打开 AI-gent，后台由 Codex 和 DeepSeek 执行任务。项目、私聊、协作、Git 和工作证据由 AI-gent 统一管理。

文档日期：2026-11-19。状态：暖色聊天工作台、Codex/DeepSeek 独立私聊与两家群内定向执行已实现。DeepSeek 已恢复运行时默认工具，Windows 终端启动错误已修复，并通过真实命令、工作区写入限制和取消验证。基础自动接力已实现，未测试，待用户验证。AI-gent 为暂定项目名。

下一阶段重点已收紧为：跨厂商交接、基于实际文件的独立复核、项目记录与成果可导出。首批代码已加入按任务保存的执行轮次、来源消息、交接要求、执行前后文件依据，以及群右上角的“任务结果”入口。结果页可查看最近 100 项任务、交接与工具记录、文件摘录，并导出 Markdown / JSON。等待中的未验收任务继续接收补充要求；确认完成或“结束任务，不验收”后，下一条消息创建新任务。结果页可按需指派另一家读取实际文件复核；只读是本轮任务要求，沿用原执行权限，不是新增的系统只读沙箱。

数据库升至 schema 11，迁移前备份已有数据库。文件依据仅采集 Git 变更候选的有界快照，包含原有修改，不等于完整项目备份；非 Git、超限、二进制、链接和未读取项如实说明。应用不自动判定复核通过或问题已修正。以上新增能力均未构建、未测试，待用户验证；操作步骤见 [任务结果与文件复核验收](docs/verification/2026-11-19-task-results.md)。

开发协作约定（2026-11-19 用户确认）：后续测试和验收由用户自行执行。开发 Agent 负责实现、说明改动和提供测试步骤，不主动运行自动化测试、真实模型探针、界面测试或其他测试任务，不为验证消耗模型额度。除非用户后续明确要求，不额外编写测试或将代跑测试作为交付前置条件。未测试项如实标注“未测试，待用户验证”。下文测试命令及验收清单供用户自行使用；既有验证记录保留为历史记录。本约定针对 AI-gent 的开发过程，不取消软件内已确认的 Agent 协作检查功能。

## 本地开发

需要 Node.js 22.12+、npm、Rust 1.90+，以及 [Tauri Windows 开发依赖](https://v2.tauri.app/start/prerequisites/#windows)（MSVC C++ 工具链和 WebView2）。

```powershell
npm ci
npm run desktop
```

第一次构建需要下载并编译 Rust 依赖。开发版使用 `local.ai-gent.desktop.dev` 应用标识，数据库写入 Tauri 解析的应用数据目录；界面右侧可查看实际位置。项目源码留在用户选择的原目录。

当前可用：Agent 导航、聊天/通讯录、搜索、创建本机群聊、邀请和管理自己的 Agent、引用回复、复制消息、@ 选择、文本附件、原生目录选择、项目切换与 SQLite 持久化。重复选择同一目录会选中已有项目。Codex 支持本机登录检测、真实模型目录、流式回复、工具记录、审批、取消和恢复。DeepSeek 支持独立私聊、消息及文件工具记录、取消和恢复；群内支持定向回复和运行时默认工具，不预设固定能力分工。群内默认支持相互 @ 和运行中插话；Git 管理、产物索引及托盘待完善。关闭窗口会退出程序并停止本软件管理的 Codex 与 Harness 进程组。

群聊可不关联项目，每群有独立上下文。现有群可从右上角“群设置”关联、更换或解除关联项目，保留群 ID 和全部聊天记录；改目录后使用新的 Agent 执行会话，旧文件不自动搬移。运行中或暂停的协作需先结束或取消。邀请只处理自己的本机 Agent，没有外部邀请。群内可用 @ 菜单或消息开头的 @Codex / @DeepSeek 指定执行者，模型目录随目标切换；不会自动唤醒所有成员。每个群、每家 Agent 各有独立执行会话。两家消息和工具记录按实际来源显示在同一群内。关联项目的群在该项目目录执行，未关联的群使用自身工作目录；同一项目的多个群会共享项目文件，但不共享厂商会话。文本附件最多三个，合计 60 KB，内容随消息发送。文字草稿可跨刷新恢复；引用和待发附件只在当前运行期间保留。界面及验证见 [设计说明](docs/06-界面设计.md) 和 [聊天工作台验收](docs/verification/2026-11-19-chat-ui.md)。

## DeepSeek 私聊

1. 安装已验证的 DeepSeek Harness `0.2.1-rc.2`，在 Harness 中配置 API 凭证，或提供它支持的环境配置。无需打开 Harness 图形窗口。应用不读取或复制密钥。
2. 启动桌面版后自动连接 Codex 与 DeepSeek，无需逐个点击连接。两家分别显示连接状态；DeepSeek 就绪后可直接选择私聊或在群内 @DeepSeek，并从已安装 Harness 内置目录选择模型。仅连接失败时需重试。连接检查验证运行组件和 SDK 初始化；认证及额度在真实发送时验证。
3. 私聊、文件工具记录及模型选择独立保存。重启或取消后，下一条消息恢复同一 Harness 会话。群内不写 @ 时广播给所有成员并协调分工；明确 @ 时仅由被点名成员处理，同一成员的新消息排队，其他群和私聊保留执行准入限制。

群内不写 @ 时广播给全部成员，明确 @ 时仅投递被点名成员；只点名一位时不自动转交另一位。同时 @ 两位成员会分别启动并显示独立状态；一位完成不阻塞另一位，停止会取消两位和待处理队列。已用真实 Codex 与 DeepSeek 验证执行重叠及独立归档，见 [并行执行验证](docs/verification/2026-11-19-parallel-members.md)。两位共用工作目录，同时修改同一文件仍需协调分工。

当前回复按消息显示。已移除应用对 DeepSeek PowerShell 和插件管理工具的禁用，按运行时默认工具集执行；保留 `workspace-write` 与现有审批。已在实际沙箱启动器上附着隐藏控制台，修复 `0xC0000142`；真实 DeepSeek 命令、中文路径文件写入、工作区外写入拒绝和进程组取消已验证，见 [终端修复记录](docs/verification/2026-11-19-deepseek-terminal.md)。普通问候直接回应，具体任务出现后才协商分工。需要额外审批的操作会被拒绝。取消会终止本软件启动的完整 Harness 进程组，已写文件保留。DeepSeek 群内执行已实现，未测试，待用户验证。群内默认支持成员相互 @，不再需要勾选开关，不固定两轮修改。Agent 在普通正文中提及对方后，应用投递消息和上下文；没有新交接时等待。用户可运行中直接插话或手动 @，消息持久排队，本轮结束后优先处理；点击停止或单独发送“停止”会取消当前执行和未执行队列。保留每群每小时 100 次执行的频率保护。新增默认协作和插话队列未测试，待用户验证。

模型目录读取、真实回复、中文目录文件写入、重启恢复、两模型切换、生成中取消与取消后恢复已验证。完整桌面点击仍受自动化工具限制，见 [DeepSeek 验收记录](docs/verification/2026-11-19-deepseek.md)。

群内执行的操作与验收步骤见 [DeepSeek 群内执行说明](docs/verification/2026-11-19-deepseek-groups.md)。自动与手动 @ 的用法见 [群内自动接力说明](docs/verification/2026-11-19-group-collaboration.md)。

## 输入 / 调用技能

在私聊或群聊输入框开头输入 `/`，可搜索技能，列表显示总数和来源。用上下键选择，Enter 或 Tab 补全，Escape 关闭候选列表；补全后填写任务并发送。也可直接输入 `/技能名 任务`，或在群内输入 `@DeepSeek /技能名 任务`。一次最多选择 8 个技能，例如 `/技能一 /技能二 任务`。普通正文、引用和附件中的斜杠不会触发技能调用。

Codex 从原生 `skills/list` 读取当前工作目录可用的技能，包括运行时开放的插件技能；不遍历插件缓存冒充已安装列表。DeepSeek 使用当前固定版本 Harness 的 SDK 适配，读取技能注册表及默认 Agent preset 的作用域，因此能包含已加载的内置及插件技能。读取目录不发送模型任务，也不创建 Agent 或聊天会话；DeepSeek 会临时启动 SDK 进程并在读取后关闭。目录读取失败会显示错误，不静默降级成不完整列表。两家原厂的模型、状态等普通命令不属于技能。

此外保留本地补充目录：共用项目及用户目录中的 `.agents/skills`；分别读取项目 `.codex/skills` 和 `.dsh/skills`。用户个人安装的 `.codex/skills` 同时供两家使用，包括指向其他位置的链接目录；DeepSeek 另读自己的用户 `.dsh/skills`。直接使用原文件，不复制安装，不改原厂配置，新增或修改技能后重新打开 `/` 列表即可读取。用户目录支持 `CODEX_HOME`、`DSH_HOME` 覆盖。按当前工作目录向上查找项目技能，同名本地技能优先使用离工作目录最近的版本，运行时返回的同名技能覆盖本地补充项。技能为包含 `SKILL.md` 的目录，支持名称、简介及 `user-invocable: false` 的常用 frontmatter 写法；本地补充读取器不解析完整 YAML。Codex 原生目录明确禁用的技能会从列表移除。技能文件共用不等于插件工具或账号连接共用，这些能力仍由各家运行时提供。

发送前按实际接收 Agent 重新查找技能。Codex 和本地补充技能附上对应文件位置，要求 Agent 先读取技能；DeepSeek 原生技能通过注册表加载正文及资源说明，避免将安装包内路径当作普通磁盘文件读取。正文以引用块附加，避免正文中的 `@` 被应用当成群内投递目标。该入口使用现有文本和文件工具，不透传原厂客户端的 `/` 命令。群内广播时，全部接收成员必须具有所选技能；缺少技能时保留草稿并提示用 `@` 指定成员。技能不会改变工具可用范围、审批或沙箱。

本功能未测试，待用户验证：在两家私聊分别输入 `/`，核对总数、来源及原厂已启用技能，选择技能执行；群内用 `@Codex /技能名 任务`、`@DeepSeek /技能名 任务` 验证定向调用；检查未知技能及广播成员缺少技能时的错误提示和草稿保留。DeepSeek 技能适配依赖当前已固定的 Harness 0.2.1-rc.2 内部接口，升级后需重新验证。

## Codex 私聊

1. 使用 Codex 桌面客户端已安装的运行组件，或安装 Codex CLI 并加入 PATH。AI-gent 检查 Windows 客户端的 `%LOCALAPPDATA%\OpenAI\Codex\bin` 和 PATH 中的运行文件，按实际版本选择较新版。使用 `codex login` 完成登录，或自行配置 Codex 支持的模型服务。
2. 打开软件默认进入 Codex 私聊并检测本机连接，无需添加项目。左侧 Codex 可随时返回；需要处理项目文件时，在“工作空间”添加并选择目录。“连接与设置”显示版本、实际路径和模型数量，不读取或复制登录密钥。
3. 选择模型并发送任务。模型更改从下一轮生效。回复和工具开始/完成记录在当前私聊显示。
4. 请求审批时，检查命令、目录或工具变更记录，再批准本次或拒绝。不支持的服务端请求返回明确错误，不自动批准。
5. 取消会请求 `turn/interrupt`，再清理 Windows Job Object 管理的整个后台进程组。只有收到中断终态并完成清理，才显示“已取消”；未确认结果显示“中断”。已产生的文件不会自动回退。

当前保留一段不绑定项目的 Codex 私聊，以及每个项目各自的一段会话。独立私聊使用 `~/Documents/Codex/AI-gent/<应用数据目录名>/codex-personal` 作为文件工作目录，不在项目列表中创建虚拟项目。旧版应用数据目录中的私聊文件会复制迁移，原目录保留，会话 ID 和消息不变。会话上下文和记录分别保存，群内不写 @ 时广播给所有成员并协调分工；明确 @ 时仅由被点名成员处理，同一成员的新消息排队，其他群和私聊保留执行准入限制。会话 ID、模型服务、运行版本、消息和工具记录保存在应用 SQLite 中。重启后可查看本地记录，下一条消息通过 `thread/resume` 恢复；版本或工作目录不匹配时停止恢复并报告错误。Codex 原生会话文件仍由 Codex 管理，因此恢复也依赖其本机历史。

已加入当前 Windows 官方客户端的“最近”兼容同步。它同时依赖无项目工作目录范围和会话来源筛选：独立 App Server 固定写入 `vscode` 来源，而本机官方客户端 26.1111 的侧栏扫描仅接收 `cli`。AI-gent 在启动恢复和每轮结束后，为自己创建的会话备份并修正索引分类与最近活动时间；真实创建方 `originator=ai_gent`、消息和执行权限均保留。原索引元数据备份在应用数据目录的 `sidebar-index-backups/<thread-id>.json`。这使用客户端内部 SQLite 索引兼容，不是稳定的官方同步 API；客户端升级、索引重建或用户自定义无项目目录后需重新验证。同步失败单独报告，不阻止普通私聊。

任务启动时请求 `workspace-write` 沙箱与 `on-request` 用户审批，并核对服务端返回配置。工作目录本身不是沙箱；不承诺限制全部读取范围。数据库现为版本 12，升级前自动生成 `*.v<旧版本>-<UUID>.sqlite` 备份，并保留原项目会话与消息。当前保存可读消息与部分工具事件，以及新任务轮次的有界文件依据，不是完整原始协议日志或项目备份包。

初次验证使用 PATH 中的旧版 `codex-cli 0.147.0-alpha.6.6`，仅返回 3 个普通模型。现已修正运行文件选择，本机选择客户端管理的 `codex-cli 0.169.0-alpha.11.1`，返回与客户端一致的 10 个普通模型。真实测试与未验收项见 [Codex 接入记录](docs/verification/2026-11-19-codex.md)。


## 群聊上下文

群内每次投递使用新的 Codex / DeepSeek 执行会话，防止重复投递的任务说明和工具记录持续累积。私聊继续恢复原会话。完整群聊原文和原厂会话文件保留。

| 本轮历史资料 | 上限（UTF-8 字节） |
| --- | --- |
| 近期消息 | 最近 20 条内，合计 12 KB；每条最多摘取 3 KB |
| 旧消息摘要 | 最近 16 条旧消息的原文摘录，合计 8 KB |
| 相关历史 | 按本轮消息关键词检索旧消息，最多 4 条，合计 6 KB |

旧消息离开近期窗口后，自动缓存开头与结尾的摘录，保留发言人和消息编号。摘要不调用模型，不把成员陈述转成已确认结论；它不保证保存所有约定。关键词检索支持中文双字片段和英文词，不提供语义检索。消息截断和关键词未命中都可能遗漏细节。

本轮还携带用户要求、投递内容和已有工作区依据，总提示正文限制为约 90 KB，给运行时包装留出空间。字节预算用于限制输入大小，不是模型的精确 token 数；单次执行中的工具输出仍由各运行时管理。数据库升级到版本 13 前会备份已有数据库。
