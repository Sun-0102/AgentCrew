## 1. 验收规则

测试负责人：用户（2026-11-19 确认）。本清单供用户自行测试和验收，不要求开发 Agent 代跑。除非用户后续明确要求，开发 Agent 不主动运行测试、调用真实模型做探针或额外编写测试；交付时说明改动、限制和测试步骤，未执行项标注“未测试，待用户验证”。本文“待验证”包含该状态。既有验证记录保留为历史记录；新增结果注明由用户提供或执行。

每条记录软件与 Agent 版本、步骤、结果、证据位置及问题编号。状态使用：待验证、通过、失败、受能力限制。P0 不能仅凭模拟界面或模型口头声明判定通过。

模型目录、认证和真实执行必须有真实接入证据。只有一个可用模型时，“多模型切换”标为待验证，不制造模型选项凑数。受能力限制的 P0 需要解决或由用户明确调整范围。

## 2. 环境、项目和模型

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| A01 | 不启动原厂图形客户端，只启动 AI-gent | 两家 Agent 可由软件后台启动并响应 |
| A02 | 缺失 Agent、Git 或登录 | 显示具体缺项及恢复入口，不崩溃、不误报可用 |
| A03 | 添加项目 A、B，目录含中文和空格 | 项目保存正确，重复目录得到明确处理 |
| A04 | A 执行中切到 B | A 仍在 A 的工作区执行，B 仅改变视图 |
| A05 | 项目路径移动或删除 | 旧记录可读，执行被阻止，并可重新绑定 |
| A06 | 非 Git 项目 | 私聊与普通任务可用；Git 功能说明不可用原因 |
| A07 | Codex 模型目录 | 下拉选项与当前配置返回目录一致，显示支持的思考强度 |
| A08 | DeepSeek 模型目录 | 下拉选项有来源和刷新时间，选定模型可真实调用 |
| A09 | 下一轮切模型 | 当前轮不变，下一轮使用新设置；不支持时明确提示 |
| A10 | 模型无权限、下线、限流或认证失败 | 保留消息，显示原因，不暗中更换模型 |

## 3. 私聊和权限

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| B00 | 不添加项目，直接进入私聊；切换到项目再返回；重启后追问 | 无需目录选择即可发送消息；独立私聊与项目记录分开；重启保留记录并恢复原会话 |
| B01 | 每家建立两段私聊，分别提供不同随机标记 | 后续追问引用正确，未把另一会话消息加入输入 |
| B02 | 重启后打开私聊 | 软件记录完整；厂商恢复结果如实显示 |
| B03 | 私聊选择文件并执行修改 | 实际目录和权限符合配置，差异能关联到执行 |
| B04 | 私聊转交群 | 仅发送用户选中的消息/产物，没有私聊全文或无关会话 |
| B05 | 只读或目录限制 | 未授权操作实际被阻止；无法保证的模式不标为已隔离 |
| B06 | 审批后继续、拒绝、请求过期 | 只影响对应请求；旧审批不能批准新任务 |
| B07 | 两个写入任务指向同一工作区 | 调度排队或引导独立 worktree，不同时写入 |

## 4. 协作闭环

当前已实现本机群创建、成员保存、独立上下文及 Codex/DeepSeek 定向执行。新增 DeepSeek 群内执行未测试，待用户验证，手动步骤见 [执行说明](verification/2026-11-19-deepseek-groups.md)。基础自动交接和任务控制已实现，未测试，步骤见 [群内自动接力](verification/2026-11-19-group-collaboration.md)。当前已按用户新决定移除逐条开关和固定修改轮次，采用默认群聊协作；下表为完整目标，不能据此视为全部已通过。新增界面验收与证据见 [聊天工作台验收](verification/2026-11-19-chat-ui.md)。邀请范围仅限自己的本机 Agent。

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| C01 | 创建群，分别选择两家模型 | 成员模型相互独立，实际请求对应设置 |
| C02 | @ Codex 或 @ DeepSeek | 只有目标成员收到执行任务，普通消息不自动唤醒全员 |
| C03 | 默认协作 | 无需勾选开关，成员可在普通正文 @ 对方，交接和上下文可查看 |
| C04 | 检查未提交修改 | 检查者获得准确差异、未跟踪文件和版本，不只看到旧 HEAD |
| C05 | 暂停群 | 后续步骤停止派发，当前执行状态仍真实显示 |
| C06 | 高频互相唤醒 | 每群每小时启动 100 次执行后暂停，保留留言，不设置固定两轮修改限制 |
| C07 | Agent 正常结束但交付缺失 | 任务不直接标完成，显示待验收或失败原因 |
| C08 | 用户中途修改需求 | 记录决策并明确影响哪些后续任务，运行中任务不被静默篡改 |
| C09 | 群内任务面板 | 当前任务、负责人、执行状态和交付文件与持久记录一致；可展开查看交接及验证证据 |
| C10 | DeepSeek 群内执行、取消和恢复 | 真实回复与文件任务可用，模型设置正确，与私聊和其他群隔离；中断不误报成功 |
| C11 | 两个 Agent 都称通过但缺少验证结果 | 显示缺少证据或未验证，不因一致意见进入已验收状态 |
| C12 | 检查任务需要 DeepSeek 当前不支持的终端工具 | 明确指派 Codex 执行并保存真实输出，或显示能力限制并停止；不扩大权限、不跳过后标通过 |
| C13 | 修改后继续协作 | 读取当前实际文件，不固定修改轮数；无新提及时等待用户反馈，不自动判定已验收 |
| C14 | 协作执行中重启或收到重复/迟到事件 | 不重复派发，不自动重放有副作用的步骤；中断和遗留文件如实显示，恢复前可核对 |

## 5. Git 与产物

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| D01 | 仓库已有未提交及暂存文件 | 软件先展示，未自动覆盖、stash 或提交用户文件 |
| D02 | 创建 worktree | 明确基线 commit、分支和路径；不假定包含未提交修改 |
| D03 | 提交选定文件 | 提交内容与选择一致，用户原暂存内容不被隐式带入 |
| D04 | 合并存在冲突 | 停止自动继续，显示冲突并保留原证据 |
| D05 | 恢复文件或 revert | 执行前预览范围，执行后记录结果；无隐式 reset --hard |
| D06 | 删除含修改的受管 worktree | 阻止直接删除，要求用户明确处理修改 |
| D07 | 工作流完成 | 没有未经操作的 push、强推或发布 |

## 6. 记录、取消和恢复

| 编号 | 测试 | 通过条件 |
| --- | --- | --- |
| E01 | 查看一次真实任务记录 | 任务、会话、模型、工作区、版本、事件、产物可以关联 |
| E02 | 模型声称测试通过但无执行结果 | 不显示成已验证通过，标注缺少证据 |
| E03 | 导出后关闭 AI-gent 和所有 Agent | Markdown、JSON 及产物可以独立阅读 |
| E04 | 导出诊断与证据 | 不含 API key、token、认证头或环境变量全集 |
| E05 | 取消长任务 | 先显示取消中，确认后才标取消；已写文件明确保留 |
| E06 | 杀死 Agent 或断开协议 | 显示失败或中断，保留已捕获事件，不假报完成 |
| E07 | 强制结束软件再重开 | running 尝试被核对；不盲目重发命令、提交或合并 |
| E08 | 重复/迟到事件、前端刷新 | 无重复任务，旧尝试不修改当前尝试终态 |
| E09 | 证据文件丢失或磁盘写满 | 明确报错和缺失，不标记证据包完整 |
| E10 | 关闭窗口留托盘、彻底退出 | 前者继续任务；后者按声明停止本软件进程树 |
| E11 | 软件退出时用户另有 Codex 进程 | 不终止软件未拥有的进程 |
| E12 | 备份与恢复 | 数据库、附件和版本匹配；错误版本有清晰提示 |
