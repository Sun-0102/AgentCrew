# DeepSeek 群内执行：交付与手动验收

日期：2026-11-19。状态：已实现；未测试，待用户验证。

本次没有运行构建、自动化测试、真实模型探针或界面测试，没有为验证调用模型。下列“预期”是用户验收标准，不是已通过的结果。仅调整现有测试中的旧表名、数据库版本和群成员能力断言，未新增测试。

## 本次改动

```text
群内 @DeepSeek → DeepSeek 模型 → 本群 Harness 会话 → 本群工作目录
                                      ↓
                           群消息、文件工具记录、取消与恢复
```

- @ 菜单或消息开头的 `@DeepSeek` 选择 DeepSeek，模型下拉切换为其目录；启动桌面版时自动连接 Harness，失败后可手动重试。`@Codex` 可切回 Codex。
- 用户反馈后补充输入触发：消息开头输入 `@` 或继续输入成员名称时自动打开成员菜单；点击成员替换当前前缀，光标移到名称后。菜单打开时 Enter 选择匹配成员，Escape 关闭；普通消息仍用 Enter 发送。此修复未测试，待用户验证：输入 `@` 后点击 DeepSeek，确认只有一个 `@DeepSeek`，原正文保留，模型目录随之切换。
- 发送接口核对实际执行者和群成员。一次只执行一个任务；启动任务和修改群成员共用准入锁，执行中不能修改当前群成员。
- 每个群的 DeepSeek 会话独立于私聊、其他群和本群 Codex 会话。群内显示两家的消息及文件工具记录，并保存实际来源。
- 关联项目的群使用该项目目录；无项目的群使用创建群时分配的目录。关联同一项目的多个群共享文件，独立会话不代表文件隔离。
- 取消只处理指定群的 Harness 进程组，确认退出后显示已取消；已写文件保留。下一条消息恢复同一厂商会话。重启后的未完成执行标为中断，不自动重发任务。
- schema 6 将旧的单一 DeepSeek 会话迁入按聊天标识保存的新表，原 thread ID、工作目录和私聊消息保留。升级前生成 `*.v5-<UUID>.sqlite` 备份。群消息沿用现有群消息表，增加 Agent 来源。

## 用户操作

关闭旧 AI-gent 窗口，在项目目录执行 `npm run desktop`，重新编译并启动。首次启动会升级应用数据库。下面的模型操作会使用用户的 API 额度。

建议使用一个专用临时项目，名称含中文和空格；不要用有重要修改的项目做写入验收。

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| 首次发送 | 新建群 A，加入 DeepSeek 和 Codex，关联专用项目。等待启动自动连接完成，用 @ 菜单选择 DeepSeek，确认模型，发送 `@DeepSeek 请只回复 GROUP_A_OK` | 模型属于 DeepSeek；回复头像和名称为 DeepSeek；Codex 不执行 |
| 文件任务 | 发送 `@DeepSeek 在当前工作目录创建 group-a.txt，内容为 GROUP_A_FILE，只使用文件工具` | 文件位于关联项目；群内有 DeepSeek 工具记录和回复；私聊没有该消息 |
| 双方显示 | 在群 A 选择 Codex，发送 `@Codex 请只回复 CODEX_A_OK`，完成后切回 DeepSeek | 两家历史仍在同一群，头像、名称、引用作者不随当前目标改变；模型下拉随目标切换 |
| 群内多轮 | 在群 A 告知 DeepSeek 一个新的随机暗号；下一轮要求不使用工具，复述暗号 | 恢复本群 DeepSeek 会话，能复述该暗号 |
| 群与私聊隔离 | 私聊给 DeepSeek 另一暗号。回到群 A 要求复述“本会话的暗号”，再返回私聊追问 | 两边各自保留自己的暗号和消息，不把私聊传给群 |
| 群之间隔离 | 新建无项目群 B，仅加入 DeepSeek，给第三个暗号并创建 group-b.txt。分别回到 A、B 追问各自暗号 | 每群记住自身暗号；B 的文件位于 B 的独立目录，不出现在 A 的项目中 |
| 取消与继续 | 在群 A 要求 DeepSeek 输出很长的编号列表，开始后取消，再要求复述 A 的暗号 | 显示停止过程后才显示已取消；后续仍恢复 A 的会话。已写文件不回滚 |
| 切换视图 | DeepSeek 在 A 运行时切到 B 或私聊，尝试发送；再回 A 取消。也可在 A 执行中打开成员管理并尝试保存 | 其他执行被拒绝；A 中显示 DeepSeek 正在运行，取消操作指向 DeepSeek；当前群成员修改被拒绝 |
| 重启与恢复 | 正常结束后关闭再打开，回 A 选择 DeepSeek 并追问暗号。另做一次执行中退出后重开 | 历史及来源保留；正常历史可恢复；未完成轮显示中断，需用户新发消息才继续，不自动重发 |
| 能力与迁移 | 请求 DeepSeek 运行终端命令；核对升级后的旧 DeepSeek 私聊、Codex 历史、项目和群成员 | 终端不执行且不放宽权限；旧记录仍可查看；下一轮可恢复旧私聊。旧数据库升级前的备份存在 |

无项目群的 DeepSeek 执行记录面板显示实际工作目录，便于核对文件位置。若文件任务尚未发送成功，面板可能没有工作目录。

隔离检查应使用随机暗号并要求模型不读文件；模型口头说“已隔离”不能替代实际结果。发现异常时记录群名、所选模型、操作顺序、界面错误和文件实际位置，不提供密钥。

## 当前限制

- DeepSeek 终端仍关闭，需要额外审批的操作仍被拒绝；不提供 SDK 审批 UI。
- 本次只增加手动定向执行，没有自动交接、群任务调度或固定协作工作流。两家仍各自恢复原生会话；要传递另一位成员的内容，请明确引用对应群消息或附上材料。
- 回复按消息更新，没有逐字流式输出。模型选项来自已安装 Harness 目录，实际认证和额度在发送时确认。
- 程序内运行状态不是业务验收结论。文件结果、取消与恢复、迁移兼容均待用户实测。

## 启动自动连接增量

已实现启动时并行连接两家 Agent，DeepSeek 默认模型优先沿用历史会话中仍可用的模型。DeepSeek 单独显示连接进度，不延迟原 Codex 初始化流程；失败时显示原因并保留重试按钮。本次未运行构建、测试或模型探针，待用户验证：重开桌面版后不点击连接，确认两家模型可选；再切到 DeepSeek 私聊和群内 @DeepSeek，确认可直接发送。未安装或配置不可用时应显示失败原因，可从设置重试。
