# 群内默认协作、插话与停止

日期：2026-11-19。状态：已实现；未测试，待用户验证。

用户更新决定：按 Pachat 的群聊方式默认支持成员相互 @，删除每次开启的复选框，不固定两轮修改，不强制角色顺序或最后一行控制格式。本文覆盖此前开关式接力的用法。本次未运行构建、自动化测试、界面测试或真实模型探针，未新增测试；仅更新旧 schema 断言。

## 现在怎么用

| 操作 | 行为 |
| --- | --- |
| 直接发需求 | 默认交给当前负责人或输入框下方显示的成员，不同时唤醒全员 |
| 手动 @Codex 或 @DeepSeek | 点名指定成员；若正文明确点名两位，则顺序投递给两位 |
| Agent @ 另一位 | 本轮正常完成后，应用投递提及和相关上下文；无须用户重新发送 |
| 执行中插话 | 输入框、@ 菜单、附件和发送按钮仍可用；消息先保存并显示待处理数量，本轮结束后优先处理 |
| 改方向 | 直接发新要求或 @ 成员；新用户消息优先，原回复未派发的交接不会越过它继续执行 |
| 暂停 / 继续 | 暂停后停止后续派发；当前一轮可继续。点击继续，或直接发送新消息即可恢复 |
| 停止 | 点击输入框或任务卡的停止；也可单独发送“停止”。取消当前执行及未执行队列，聊天和已写文件保留 |
| 没有新提及 | 等待新消息，不强迫另一位回复，也不自动判定验证已通过。用户可点击“确认完成” |

用户运行中插话不是实时改写正在执行的厂商 turn，已有这一轮会继续到结束；需要立即中断时点击停止。单独发送“停止”“停止执行”“停止任务”“停止协作”“取消任务”“stop”或“cancel”也会触发停止；引用、附件或长段文字中的这些词仍按普通资料处理。

Agent 提及可位于正文任意位置，使用精确成员名。代码围栏、缩进代码、行内代码、显式引用和附件元信息不触发；正文同一成员多次提及只投递一次，自指不唤醒自己。成员可根据任务决定如何分工，完成后正常报告即可，没有特殊收尾口令。

两家使用各自所选模型。群里只有一个成员时也可直接聊天；提及不在群内或未配置模型的成员会停止该次交接并说明原因，不伪造连接。模型修改用于后续用户投递，不改变已开始的一轮。

## 用户手动验收

1. 在原终端按 Ctrl+C 结束旧开发进程，再执行 `npm run desktop`，避免遗留 Vite 占用端口。首次运行升级为 schema 8，先备份旧数据库。原项目、群、关联目录、聊天和任务记录应保留。
2. 进入含两位 Agent 的测试群，等待自动连接就绪。不应再有“允许 Agent 相互 @”勾选框或固定两轮提示。
3. 直接发送以下文字任务，观察 Agent 自己交接。该步骤会使用真实模型额度；任务不要求文件工具。

```text
@DeepSeek 请和 Codex 做一次文字交接演示，不要读写文件、运行命令或启动子代理。
你先回复 PLAN_OK，再把“只回复 CODEX_OK”的工作交给 Codex，并在正文提及对方。
Codex 收到后回复 CODEX_OK，再请 DeepSeek 核对，并在正文提及对方。
你看到结果后只报告是否收到，等待我反馈，不再交回。
```

4. 预期 DeepSeek → Codex → DeepSeek 自动回应，无须再次勾选或发送。没有下一次提及时显示“等待新消息”，执行次数不再增加。
5. 再发实际文件任务，例如“请与 Codex 协作，在当前目录创建一个可离线打开的计数器 HTML；你先列验收条件，交给 Codex 实现，再读取文件核对。发现问题就协作修正，最后报告实际检查与未验证事项”。核对实际目录和工具记录；不能仅凭模型口头结论判定通过。

| 验收项 | 操作 | 预期 |
| --- | --- | --- |
| 普通手动 @ | @Codex 要求只回复 HELLO，不交给别人 | 只回应一次，之后等待；没有强制 DeepSeek 检查步骤 |
| 正文提及 | 要求交接时把对方的提及放在正文中间，最后另写正常结语 | 仍可交接，不依赖最后一行格式 |
| 不固定两轮 | 用纯文字任务要求双方各完成 4 个有编号的小步骤，再正常收尾 | 超过旧 6/7 次执行后仍可继续；未超过实际执行频率保护前不因旧轮次停止 |
| 执行中插话 | 一位生成长回复时，直接发送“新增要求：请把最终结论改成三行”，或 @ 另一位给新任务 | 消息立即入群，显示待处理数；本轮结束后先处理用户留言，再考虑 Agent 交接 |
| 多条留言 | 连续发两条不同的补充，分别点名成员 | 每条保留且只投递一次；按队列顺序处理，提示中用户最新要求优先 |
| 停止排队任务 | 运行中插入两条留言，再点击停止 | 当前执行被取消或明确显示未确认取消；后续留言和旧交接不再执行，消息仍可查看 |
| 文字停止 | 运行中单独发送“停止”，或“@Codex 停止” | 按群级停止处理，不等到该留言的普通执行轮；已写文件不回滚 |
| 暂停与恢复 | 暂停后等待本轮结束，再发新消息 | 无须先点击继续；新消息恢复处理并优先于旧 Agent 交接 |
| 引用和代码 | 只把成员提及放在引用或代码块里；添加带有成员提及的文本附件 | 不因资料中的名字唤醒其他成员；附件包含反引号围栏时仍按资料处理 |
| 停止后继续 | 停止后再显式发新任务 | 只运行新任务；不会重发被取消队列或旧提及 |
| 重启 | 运行中或有待处理消息时退出再打开 | 聊天和留言仍在，原执行标中断，队列不自动重发；由用户核对后重新指派 |
| 失败 | 模型调用或目录校验失败 | 停止后续执行，未执行留言保留在聊天里，不自动重试副作用 |
| 群与私聊隔离 | 比较本群、另一群和独立私聊 | 本次输入和上下文不自动带入其他聊天；全应用仍顺序执行 |

## 执行保护和限制

- 不再使用单任务固定总轮数。保留每群每小时 100 次执行的频率保护；触发后暂停并保留未执行留言，用户可稍后继续或停止。它不表示一个任务只能修改两轮。
- Agent 每轮结束后才读取提及和派发，按群、当前执行者、会话/可用 turn ID 和本轮消息序号核对。用户新消息可覆盖尚未派发的旧交接，不扫描私聊或历史任务来唤醒成员。
- 交接包含来源消息、用户目标及新要求、群内近邻聊天、实际工具记录、工作目录、HEAD、Git 状态、未跟踪路径和已跟踪差异。上下文有长度和数量限制，截断明确标记，不能把它当作完整不可变证据。
- 已有沙箱、审批、目录核对及进程组取消方式保持有效。DeepSeek 终端仍不可用；需要命令时可交给 Codex。
- 本群活动执行或暂停的任务需要先结束/停止，才能修改群成员或关联项目。其他群不能与本群同时执行；暂停且当前轮结束后可以执行独立私聊。
- 软件保留群级接力，不安装 Pachat 的外部监听器、登录项或云端服务。不承诺睡眠、关机或彻底退出后的持续运行。

## 现有群关联项目增量（已实现，未测试）

入口：打开原群 → 右上角“群设置” → “关联项目”选择项目 → 保存。没有项目时先到“工作空间”添加本地目录。也可以选择“不关联项目，使用群专用目录”解除关联。

实现沿用现有字段，无新增数据库迁移。保存时在同一事务内更新群的 project_id 和会话工作目录，保留群 ID、群名称设置、成员、历史消息和协作记录。仅在项目关联发生变化时，解除本群 Codex/DeepSeek 的原执行会话绑定；原厂会话文件不删除，原 thread ID 与前后目录保存在可展开的目录变更记录。下一条任务创建新执行会话，不自动注入全部旧聊天；延续旧任务时请引用群内相关消息。普通改名、改成员或原项目不变时不重建会话。

旧文件不自动搬移或复制；切换到项目 B 不会把项目 A 的文件复制进去。解除关联后使用本群专用目录。目录不存在或不可读时拒绝保存；运行、审批、取消中及暂停的自动协作不能改关联。原目录的待验收任务会标为中断，不能拿旧检查结果验收新目录。

以下步骤供用户执行；本次未运行构建、测试、模型探针或界面操作，仅调整原有测试调用的参数，未新增测试。

| 操作 | 预期 |
| --- | --- |
| 在有历史消息的原群中选择“测试项目”并保存 | 群名和群 ID 不变，原消息仍在；标题下显示“关联项目 · 测试项目” |
| 分别手动 @Codex 和 @DeepSeek 创建不同标记文件 | 两个文件都位于所选项目目录，不再写入原群专用目录 |
| 查看原群专用目录和聊天中的目录变更记录 | 原文件保留；变更记录含前后目录和旧执行会话索引 |
| 重启应用后再进入原群 | 项目关联和全部历史仍保留，后续执行继续使用所选项目目录 |
| 从项目 A 切到 B，再解除关联 | 后续任务按所选目录执行；各旧目录文件保留；聊天记录不清空 |
| 项目选择保持不变，只改群名或成员 | 原执行会话不因保存设置而被重建 |
| 正在执行或暂停自动协作时保存关联；或选择已被移动/删除的目录 | 显示明确错误，原关联、原会话及消息不变 |

## 简洁聊天界面增量（已实现，未测试）

默认主界面只显示用户/Agent 消息与输入框上方一行状态。工具、派发、系统日志、目录变更和任务卡从聊天流移到右上角“聊天详情”，记录保留。DeepSeek 能力说明不再常驻输入区。

用户检查：原群的消息仍在；执行时只有一行当前状态，不再堆叠工具条目和大任务卡；右侧详情能展开原记录、查看任务模型并暂停/继续；审批时主状态提示“查看请求”，详情内可批准/拒绝；失败时“查看详情”可读完整原因；输入框的发送与停止仍可用，暂停后也能停止排队任务。此改动仅调整界面呈现，未运行构建、自动化测试、界面测试或模型探针。

## 同轮气泡合并增量（已实现，未测试）
