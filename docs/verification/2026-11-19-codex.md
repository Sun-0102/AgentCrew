# Codex 最小接入记录

日期：2026-11-19。本文记录真实后台测试，不代替完整桌面操作验收。

## 官方最近兼容修复（当前结果）

此前仅检查了侧栏无项目登记，结论不完整。进一步核对实际运行的 MSIX 官方客户端 `OpenAI.Codex_26.1111.2228.0` 的安装资源，确认两个条件：

1. 无项目列表可按 `~/Documents/Codex/` 的工作目录前缀收录，无需直接改写 `projectless-thread-ids`。
2. 当前侧栏扫描的来源集合仅为 `cli`。独立 `codex app-server` 却固定创建 `vscode` 来源；改变 `clientInfo.name` 只改变 `originator`。该行为也见 [OpenAI Codex issue #23442](https://github.com/openai/codex/issues/23442)。

最终修复：

- 私聊工作目录迁至 `~/Documents/Codex/AI-gent/<应用数据目录名>/codex-personal`。复制后切换记录，保留原目录；遇到目录冲突、链接或正在执行的会话时停止迁移，避免覆盖文件。
- 启动时恢复同一个私聊 thread，更新原生工作目录并设置可见标题；首次发消息也设置标题。
- 仅对本应用 SQLite 已绑定、原生 `originator=ai_gent` 且工作目录匹配的 thread，将 Codex 状态库的索引来源分类从 `vscode` 兼容为 `cli`，并更新最近活动时间。执行权限和原生消息文件均不修改。其他创建方拒绝处理。
- 原索引字段先写入应用数据目录 `sidebar-index-backups/<thread-id>.json`，原始备份不覆盖。启动和每轮结束后重做兼容检查；同步失败不改变任务结果，也不阻止连接聊天。

实测结果：原有“你好”对话 thread ID 不变、消息不变；官方 `read_thread` 可读取同一条记录，标题为“AI-gent 私聊”。通过官方 `set_thread_title` 对同一标题做了一次更新，促使当前已运行客户端摄取记录。随后在官方 `codex.db` 的 `local_thread_catalog` 查到该 thread，`source_kind=cli`、`missing_candidate=0`，并用当前无项目目录前缀筛选查到该记录；这一步比此前只通过历史接口读取更接近实际侧栏数据源。

13 项本地测试通过，包含目录迁移保留文件/原目录/会话、活动会话保护、目标冲突保护，以及索引创建方校验和原始备份。真实无项目私聊及重启恢复复测通过。未取得官方客户端最终侧栏截图。

限制：这是当前版本的内部索引兼容方案。原生 JSONL 保留原始 `vscode` 来源，官方索引重建可能恢复该来源；AI-gent 启动或下一轮结束会重新检查。官方客户端索引摄取和窗口刷新有自己的时机，本次已运行实例借助官方标题更新触发摄取，不能把它声称为任意客户端版本都实时同步的稳定协议。自定义官方无项目根目录尚未适配，客户端更新后需复核。

下面的“尚未接入”结论为修复前排查记录，以上结果优先。

## 官方客户端侧栏可见性

用户报告 AI-gent 的无项目私聊没有出现在官方客户端“最近”，重启仍未出现。先前将其归为侧栏未刷新不准确。

进一步只读核对本机客户端代码及状态：

- 会话已存在 Codex 状态库，`source=vscode`、`originator=ai_gent`、未归档，工作目录为 AI-gent 独立私聊目录。
- 官方 `read_thread` 和 `list_threads` 的历史/最近接口都能读到该会话。这证明后台记录存在，不能证明前端当前分组会展示它。
- 本机官方客户端的无项目列表筛选包含 `projectless-thread-ids` 登记项，以及客户端认可的无项目目录范围。该会话 ID 未出现在登记项内，AI-gent 的专用目录也不在官方无项目目录范围内。
- 当前版本独立 App Server 创建会话不会执行官方桌面客户端的无项目登记。`0.169.0-alpha.11.1` 导出的 ClientRequest schema 未包含桌面客户端 `get-global-state` / `set-global-state` 方法。
- 已用受支持的 `navigate_to_codex_page` 打开现有会话，返回 `navigated:true`；导航后无项目登记仍不存在。因此打开会话也不等于修复侧栏收录。

当前结论：AI-gent 无项目私聊可保存和恢复，但官方“最近”侧栏自动收录尚未接入。未直接改写官方客户端内部状态文件，也未把后台可读或导航成功记录为侧栏展示验收通过。

## 无项目私聊

根据用户要求，启动默认进入“Codex 私聊”，左侧提供常驻入口，无需添加或选择项目。选择项目后仍打开该项目独立会话，点击左侧私聊可返回。

数据库升级到 schema 3，新增 `conversations` 表区分不绑定项目的私聊与项目会话；消息、会话引用改为 conversation ID。迁移前备份旧数据库，保留项目会话 thread ID 与消息。独立私聊使用应用数据目录下的专用工作目录，不往项目列表插入虚拟项目。

验证：10 项本地测试通过，包含无项目私聊目录/记录持久化、项目记录分离，以及 schema 2 的项目会话与消息迁移。`installed_codex_personal_chat_and_resume` 真实测试通过：零项目情况下完成私聊，重启后台和数据库后同一 thread 记住上一轮随机暗号。此次未重复进行桌面点击验收。

以下章节中的“每项目一段会话”“schema 2”等内容属于前次交付记录；当前另有一段不绑定项目的独立私聊。

修正后扫描 PATH 入口与 Windows 客户端管理的运行文件，执行 `--version` 并按语义版本选择较新版；未修改用户 PATH、全局配置或登录信息。界面显示实际版本和可展开的运行路径、模型数量。

新增旧 PATH/新桌面组件选择回归测试，本地测试现为 8 项通过。新版默认模型 `gpt-6.2-sol` 的中文目录文件写入、多轮上下文、进程重启恢复及取消后工具进程退出也已复测通过。未逐一调用全部 10 个模型。以下原始交付记录保留首次验证的版本和结果。

## 交付

- Rust 启动 `codex.exe app-server --listen stdio://`，逐行解析 JSON 消息，关联请求 ID、响应、通知和错误；stderr 单独排空，不保存认证诊断。
- `initialize`、`initialized`、`account/read`、分页 `model/list`。
- 所选项目的 `thread/start`、`turn/start`、`thread/resume`、`turn/interrupt`。
- 模型选择、文字增量、工具开始/完成记录、命令和文件审批按钮。
- SQLite schema 2 保存每个项目的一段会话和可读记录。schema 1 升级前用 SQLite `VACUUM INTO` 备份。
- 核对服务端实际返回的执行目录、沙箱、审批模式；恢复时核对版本与模型服务。
- Windows Job Object 绑定 Codex 后台，退出或取消时清理全部子进程。一次只运行一个项目任务。

## 取消问题与处理

初始实现仅发送 `turn/interrupt`。两次真实测试均收到中断终态，但 PowerShell 休眠工具仍存活，第二次等待 5 秒后仍未退出，因此未将初始实现记为通过。

最终实现使用 Windows Job Object 管理 App Server 及其子进程。取消时先请求中断，等待终态，再终止进程组。只有确认终态且完成清理才显示“已取消”。真实复测通过。下一条消息重新启动后台，并恢复同一会话。文件修改不会随取消回退。

- Windows 已验证；其他操作系统的子进程清理未验证。
