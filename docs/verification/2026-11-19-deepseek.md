# DeepSeek 独立私聊接入与验证

日期：2026-11-19。范围仅为 DeepSeek 独立私聊；未开始双 Agent 协作，也未开放 DeepSeek 群聊执行。

## 接入与数据

- 本机运行文件：`D:\deepseekharness\DeepSeek Harness.exe`，版本 `0.2.1-rc.2`。从 Windows 安装登记发现路径，也可用 `AI_GENT_DSH_DESKTOP` 指定。此适配器固定已验证版本，升级后先核对兼容性。
- 使用已安装客户端的 CLI host，以 `ELECTRON_RUN_AS_NODE=1` 启动 `--profile ai-gent-sdk`；首次从官方 `sdk` 模板生成独立 profile。Rust 直接连接 JSON-RPC stdio，没有 Python 协议中转，也没有自建模型 Agent 循环。
- 线协议按本机包源码验证：`initialize`、`session/prompt`、`session/wait`、`session/resume`、`session/working-directory/get`、`shutdown`。SDK 握手版本 `0.0.1`，不能用它代替实际运行组件版本。
- Harness 自行解析现有 API 凭证配置。应用不读取、显示或复制 `.credentials.yaml` 的密钥，也不复用网页登录。连接检查只核对运行组件、目录和 SDK 初始化；真实认证和额度以实际发送结果为准。
- 模型从已安装 Harness 的公开配置导出读取，不在前端硬编码：`deepseek-flash`（DeepSeek-V4.1-Flash）、`deepseek-v4-pro`（DeepSeek-V4-Pro）。两项都完成真实调用。来源为内置目录，不声称在线 `/models` 查询。
- 数据库 schema 5 新增独立 DeepSeek 会话和消息表。升级前生成 v4 备份，保留 Codex 会话和消息。私聊文件位于应用数据目录下 `runtimes/deepseek/workspace`；不创建项目。
- profile 使用额外 patch 固定 `workspace-write` 和 `ask`，关闭本应用的 Harness 会话云日志插件、插件安装工具及当前不可用的 PowerShell 工具。运行日志仍依赖 Harness 原生本地历史以恢复上下文。cwd 不是完整读取隔离承诺。
- 两家任务入口共用执行准入锁，并检查数据库中的运行状态。仍然一次执行一个任务。DeepSeek 不写入 Codex 会话或官方 Codex 索引。

## 已确认的限制

1. 当前版本 SDK 仅转发持久化消息和工具事件，没有实时逐字增量；界面按消息更新，不模拟打字流。
2. 当前版本没有独立中断 RPC。取消通过停止本软件管理的完整 Windows Job Object 并等待 Harness 进程退出实现。不是厂商中断回执；已写文件不会回滚。
3. 原始 PowerShell 沙箱测试返回 `3221225794`（`0xC0000142`）。在本应用进程组外直接运行官方 SDK 也能复现，因此当前关闭 PowerShell 工具，不降级成无沙箱执行。长休眠工具和工具子进程的取消验收未通过；已通过的是生成中取消及 Harness 进程退出。
4. 当前版本不提供 SDK 审批回调。需要额外批准的操作保持拒绝，不自动授权。没有实现审批 UI、DeepSeek 项目会话、多会话管理或群聊执行。
5. SDK 原始错误和 stderr 不写入普通聊天记录；错误会给出检查模型服务、额度或权限的提示。数据库保留可读消息及工具开始/结果，不是完整原始协议证据包。
