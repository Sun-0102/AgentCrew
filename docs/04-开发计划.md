# 开发计划

版本：0.1。日期：2026-11-19。采用阶段退出条件，不在技术验证前承诺日历工期。

## 1. 实施原则

先验证后台接入，再实现会话与项目，再做协作和 Git。每阶段都交付可运行结果和证据，不以界面截图代替真实接入。

```text
S0 接入验证 → S1 桌面与数据 → S2 双 Agent 私聊
                                   ↓
S5 发布验收 ← S4 Git 与证据 ← S3 协作闭环
```

## 2. 阶段计划

| 阶段 | 工作 | 可检查交付 | 退出条件 |
| --- | --- | --- | --- |
| S0 | 固定 Codex、Harness 版本；验证协议、模型、项目、连续对话、取消和恢复 | Rust 接入探针、脱敏事件夹具、能力矩阵 | 两边可在 Windows 指定目录执行真实任务，关键限制已记录 |
| S1 | Tauri、React、Rust 工程；迁移、项目登记、IPC、日志和托盘 | 可运行桌面壳及持久项目列表 | 添加两个项目并重启后仍存在；切换视图不改运行上下文 |
| S2 | 账号状态、模型目录、独立私聊、流式事件、审批与取消 | 两边完整私聊流程 | 每家至少一段多轮对话，模型选择、错误、记录及重启核对通过 |
| S3 | 群成员、@、任务状态、交接包、默认群聊协作 | 拆解→实现→检查→修改的真实记录 | 用户只发一次任务，两家按依赖完成且无私聊泄漏或循环派发 |
| S4 | Git 状态、差异、worktree、提交、合并、回退；证据导出 | 完整本地代码任务和离线证据包 | 脏目录保护、冲突处理、未提交文件交接及独立阅读通过 |
| S5 | 异常恢复、资源与路径兼容、安装包、全量 P0 验收 | Windows 安装包、验收报告、已知限制 | P0 全部通过；阻塞问题解决；支持能力与界面一致 |

阶段可重叠编写静态界面，但 S0 未通过不能把模拟接入界面宣称可用。S3 的早期验证可使用专用测试仓库和顺序写入；完整 Git 管理在 S4 收口。

## 3. S0 最小验证清单

1. 在 Windows 上分别启动 codex app-server 和 dsh --profile sdk，记录来源与版本。
2. 完成认证检查和模型目录读取，确认至少一个真实可用模型。
3. 在含空格、中文的测试目录创建一个唯一标记文件，核对实际写入位置。
4. 同一会话连续两轮，第二轮引用第一轮提供的随机标记。
5. 两个独立会话使用不同标记，检查上下文未串用。
6. 尝试下一轮切模型；若只有一个可用模型，用协议夹具验证 UI，真实切换标为未验证。
7. 捕获回复、工具执行、退出及错误事件，建立与内部事件的映射。
8. 取消长任务，检查厂商回执、派生进程和已产生的文件。
9. 关闭运行实例再恢复；确认哪些状态持久，哪些需要重建。
10. 核对凭证落盘、工具权限和目录边界；不把 cwd 当 sandbox。

若 Harness 无法满足关键 P0，不得悄悄改用模型 API 自建 Agent、网页自动化或 headless 冒充完整 SDK 接入。记录阻塞点和替代方案，由用户决定是否调整范围。

## 4. 开发工作包

| 工作包 | 必须实现 | 主要验证 |
| --- | --- | --- |
| 进程与协议 | framing、请求映射、退出、超时、stderr、进程树 | 分片消息、进程崩溃、取消、未知事件 |
| 存储 | 迁移、项目/会话/任务实体、事件序号、产物索引 | 重启、重复事件、磁盘失败、缺失文件 |
| 私聊与模型 | 模型来源、会话绑定、流式回复、上下文恢复 | 跨项目、跨会话、不支持模型、切模型 |
| 调度 | @、依赖、分派、轮次、暂停、重试与验收 | 重复派发、旧回执、暂停时仍运行、循环上限 |
| Git | 机器输出解析、路径参数、工作区锁、worktree、差异 | 脏目录、暂存区、冲突、非 Git、中文路径 |
| 证据 | 原始/标准事件、产物哈希、脱敏、导出 | 秘密不泄漏、独立阅读、文件缺失不误报完整 |
| 桌面 | 权限 IPC、项目/私聊/群视图、托盘与退出 | 前端重载、禁用状态、错误恢复、窗口关闭 |

## 5. 测试策略

2026-11-19 用户确认：后续测试和验收由用户自行执行。开发 Agent 负责实现、说明改动、列出限制及提供可操作的测试步骤；不主动运行自动化测试、真实模型探针、界面测试或其他测试任务，不为验证消耗模型额度。除非用户后续明确要求，不额外编写测试，不将代跑测试作为交付前置条件。

本计划的阶段退出条件、最小验证清单和“主要验证”列均供用户测试和判断完成状态，不能理解为授权开发 Agent 自动执行。开发完成但未测试的项目标注“未测试，待用户验证”；不能将实现完成直接写成验收通过。既有验证记录保留为历史记录。

用户自行测试时，可按验收清单覆盖协议、状态、隔离、恢复和 Git 保护。Git 测试建议使用临时仓库，不在真实项目中做破坏性测试。夹具只证明解析兼容，不能证明当前账号和模型可用；用户提供的结果与既有记录应注明来源。

本约定针对 AI-gent 的开发过程；软件内 DeepSeek 检查、Codex 修改和结果核对等已确认产品功能仍保留，实际任务按用户指派执行。

## 6. 发布和运维

- 开发构建与正式安装使用不同应用标识及数据目录，避免污染真实记录。
- 安装程序检查 Windows 所需桌面组件、Agent 和 Git 的可用性。缺失时提供明确安装说明，未经用户操作不静默修改全局运行环境。
- 记录软件、协议、Agent、数据库 schema 的版本。Agent 更新先做兼容检查，不默认认为最新版本兼容。
- 数据库迁移前备份；失败时停止写入，不能覆盖旧数据库继续运行。
- 导出可读记录与可恢复备份分开说明。备份包含数据库、产物和版本清单，不默认包含账号密钥。
- 发布报告列出已支持平台、模型验证情况、取消/恢复限制，以及尚未完成的验收项。
