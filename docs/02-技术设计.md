# 技术设计与开发约定

版本：0.1。日期：2026-11-19。本文为目标架构，不表示代码已经存在。

2026-11-22 最新改进架构见 [Agent 自助接入与持续协作改进方案](08-Agent自助接入与持续协作改进方案.md)。涉及自助配对、动态 Agent 身份、唯一后台调度、持久队列、托盘和恢复的设计以该方案为准；厂商执行层继续复用本机 stdio。当前仅形成文档，未实施。

## 1. 技术栈

| 层 | 选择 | 边界 |
| --- | --- | --- |
| 桌面 | Tauri 2 | 窗口、托盘、应用目录、受限 IPC |
| 界面 | React、TypeScript、Vite | 展示、交互、订阅事件；不直接运行 Shell |
| 后台 | Rust、Tokio、Serde | 进程、协议、任务调度、存储与 Git |
| 数据库 | SQLite，建议 rusqlite | 结构化记录、索引、迁移；数据库操作不阻塞流读取 |
| 代码管理 | Git CLI | 参数数组调用，不拼接 Shell 命令 |
| Agent | Codex App Server、DeepSeek Harness SDK profile | 独立进程，按适配器统一能力 |
| 测试 | Rust 测试、Vitest、协议回放夹具 | 真机接入测试与模拟测试分开 |

依赖安装时选择互相兼容的版本并提交锁文件。首版不额外增加 Node.js 后台服务、Python 中转层、Redis、云数据库或大型多 Agent 框架。Agent 自身需要的运行组件不在此限制内。

## 2. 结构

```text
React UI
   │ Tauri commands / events
Rust application service
   ├─ Project / Conversation service
   ├─ Task scheduler / Context handoff
   ├─ Agent adapters ── Codex / DeepSeek child processes
   ├─ Git service ───── git child process
   └─ Record store ──── SQLite + artifact directory
```

Rust 后台唯一负责执行调度。前端断开或重载不能造成重复派发。应用只管理自己启动的进程，不按进程名称批量结束用户其他 Codex 或 DeepSeek 进程。

建议代码结构：

```text
src/
  features/projects/
  features/conversations/
  features/teams/
  features/git/
  features/evidence/
  shared/
src-tauri/
  src/commands/
  src/services/
  src/agents/{codex,deepseek}/
  src/storage/
  src/git/
  migrations/
  tests/fixtures/
docs/
```

按实际功能建立模块，不为未接入厂商预建空目录或通用插件系统。

## 3. 进程与生命周期

Rust 使用异步子进程管理 Agent，分离 stdout 协议流和 stderr 诊断。协议流支持分帧、请求关联、超时、未知事件和子进程退出处理。限制消息与日志缓冲大小，防止管道阻塞。

Windows 使用 Job Object 或经验证的等效机制管理本软件进程树。需验证包装脚本、实际 runtime 和派生工具进程都能正确退出。关闭窗口留托盘与彻底退出是两个操作。

首版每个私聊或群成员会话采用受控的独立运行实例；设置并发上限，空闲实例可关闭，再通过持久会话恢复。优先保证工作目录和会话配置明确，避免全局配置串扰。若底层无法无损恢复则明确提示，不伪装连续上下文。

应用异常退出后启动恢复程序：核对持久状态与实际进程。无法证明仍运行的尝试标为 interrupted，不自动重复发送执行请求。关闭窗口继续执行，彻底退出停止执行；崩溃期间的持续运行不作首版保证。

## 4. 目录和存储

运行数据放入 Tauri 解析的系统应用数据目录，禁止写死开发机路径。用户项目源码留在原目录。

```text
<app-data>/
  ai-gent.sqlite
  artifacts/<project-id>/<attempt-id>/
  runtimes/deepseek/<instance-id>/
  diagnostics/
  backups/
```

Git worktree 建议放在仓库同盘、用户可见的受管目录，创建前验证磁盘、路径和仓库关系。路径表保存原路径与规范化路径；不要只靠字符串前缀判断归属，处理大小写、符号链接和 junction。

文本记录在 SQLite；大型命令输出、差异、图片与文件保存在产物目录。文件先写临时路径、完成后原子重命名，再登记索引；启动时识别缺失文件和孤立临时文件。导出不能跟随任意路径读取项目外文件。

## 5. 核心数据实体

所有 ID 使用不依赖显示名称的稳定标识。时间保存 UTC，界面按用户时区显示。JSON 扩展字段带 schema_version。

| 实体 | 主要字段 |
| --- | --- |
| projects | id、name、primary_root、archived_at |
| project_roots | id、project_id、path、role、access_mode |
| repositories | id、project_id、path、git_dir、default_branch |
| conversations | id、project_id、kind(private/group)、title |
| participants | id、conversation_id、agent_kind、requested_model、options |
| agent_sessions | id、participant_id、runtime_version、provider_session_id、workspace_id、state |
| messages | id、conversation_id、sender、recipient、body、reply_to、visibility、created_at |
| tasks | id、conversation_id、spec、acceptance、owner、state、revision |
| task_dependencies | task_id、depends_on_task_id |
| attempts | id、task_id、session_id、state、requested_model、actual_model、started_at、ended_at |
| events | id、attempt_id、sequence、type、payload、observed_at、source_id |
| artifacts | id、attempt_id、relative_path、kind、sha256、size、capture_source |
| approvals | id、attempt_id、provider_request_id、scope、state、decision |
| git_operations | id、attempt_id、repository_id、operation、base_commit、result_commit、result |
| handoffs | id、source_attempt_id、target_task_id、message_id、artifact_manifest |

账号记录仅存认证方式和凭证引用，不存明文密钥。模型目录可缓存并记录来源、时间和可用状态；实际调用失败优先于缓存判断。

事件序号在执行尝试内递增，唯一约束防止重复插入。任务派发通过数据库事务和 revision 检查防止重复消费。外部副作用无法与数据库形成原子事务，状态不确定时进入人工核对，不宣称恰好执行一次。

## 6. IPC 设计

前端仅调用明确业务命令，例如 project_add、conversation_create、model_list、message_send、attempt_cancel、approval_resolve、git_diff、git_commit、evidence_export。

不提供任意 Shell 执行或任意文件读取的前端接口。参数在 Rust 重新验证，检查 project_id、conversation_id、workspace_id 的关联。前端传来的路径和权限都不能直接信任。

实时事件用于刷新界面，数据库为最终事实来源。前端先订阅再取快照，并以序号补齐缺口；重连从最后 sequence 查询。高频文字增量可批量持久化，运行终态前必须刷新缓冲。不能仅依赖 Tauri 事件保存历史。

## 7. 项目、并发与 Git

- 本地普通目录可运行 Agent；Git 功能在缺仓库时禁用，并解释原因。
- 同一工作区最多一个软件调度的写入任务。只读任务也须记录观察的版本，避免把读取到的变化误认为固定快照。
- 独立并行写入任务使用不同 worktree；Git worktree 不是权限隔离或完整环境隔离。
- worktree 默认从已知 commit 创建，不能假定包含用户未提交文件。需要这些文件时先由用户决定提交或显式快照。
- 交接保存 base commit、修改差异、未跟踪文件清单及测试结果。检查者审查精确快照，不能只检查默认分支。
- Git 调用用 argv 和 cwd；解析使用机器可读输出（如 porcelain），不依赖本地化提示文本。
- 提交只包含选定文件，保留用户既有暂存意图；发现已有暂存文件时明确展示，不隐式提交全部。
- merge 或 cherry-pick 前检查目标仓库状态与预期基线。冲突阻止自动继续，保留证据并让用户选择处理方式。
- 恢复文件和 revert 必须展示作用范围；不自动执行 reset --hard、clean -fd 或删除含修改的 worktree。
- 任务成功不等于已提交，提交成功不等于已合并；界面分别显示。

## 8. 凭证、权限与执行边界

Codex 使用自身支持的认证流程和配置，不复制凭证到通用数据库。DeepSeek 密钥优先保存于系统凭证存储，并只提供给所需运行实例；必须实测 Harness 是否另行持久化或向子工具继承。若它写入自身凭证文件，限制本机访问并明确告知，不能声称全部凭证均由系统保险库保护。

选择 cwd、设置 UI 只读和 Tauri capabilities 都不能单独限制后台 Agent 的全部文件访问。Codex 采用实际支持的 sandbox 与审批配置。DeepSeek 的只读或目录限制必须由运行环境工具策略验证；无法可靠实现时禁用该模式或标注未隔离，不能仅靠提示词实现权限。

不默认向所有成员授予完整权限。群消息、仓库内容和交接文档均按任务数据处理，不能据其内容绕过用户审批。审批通过统一界面处理，并关联具体请求和执行尝试，过期请求不得批准新尝试。

## 9. 证据与可观察性

标准证据包包括任务说明、成员配置、投递消息、规范化事件、可获取的原始事件、代码基线、差异、验证输出、产物清单及异常记录。

只记录实际能观测的事件。运行环境不提供某项工具记录时标注 unavailable。Hash 用于检测导出或文件变化，不代表 Agent 回报真实或结果正确。原始协议日志也需脱敏，禁止记录认证头、环境变量全集或密钥输入。

首版支持 Markdown + JSON + 附件目录导出。导出清单记录版本和文件哈希，用户可不启动任何 Agent 独立阅读。截图和屏幕录像不是默认采集项。
