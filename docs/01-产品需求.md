# 产品需求文档

版本：0.1。日期：2026-11-19。状态：待实现。

## 1. 产品目标

让用户在一个桌面软件中管理项目、选择不同 AI、进行私聊或协作，并保留可独立查看和导出的工作记录。

```text
直接私聊，或选择项目 → 项目私聊/协作群 → 分配任务 → Agent 后台执行
                                      ↓
                   查看证据、代码差异 ← 检查和修改
```

用户不需要在 Codex、DeepSeek 客户端之间复制任务、搬运回复或寻找证据。软件使用各家 Agent 的后台执行环境，保留其实际工具能力。

## 2. 目标用户和主要场景

首版服务本机单用户，Windows 桌面优先。

2026-11-19 界面范围确认：参考聊天软件的 Agent 导航、私聊、群聊和邀请。沿用现有暖色。邀请仅选择自己的本机 Agent；不接外部 Agent，不扩展多人协作。当前已实现 Codex 定向群聊，DeepSeek 执行及自动工作流仍待完成。

| 场景 | 预期行为 |
| --- | --- |
| 处理不同项目 | 添加多个项目，切换项目查看其会话、任务和产物 |
| 单独询问 AI | 建立 Codex 或 DeepSeek 私聊，连续追问和执行任务 |
| 比较或选择模型 | 为不同会话选择该 Agent 当前可用的模型 |
| 两个 AI 交接 | 群内将分析、代码版本和检查结果交给指定成员 |
| 追查工作过程 | 查看谁执行、输入是什么、改了什么、怎样验证 |
| 管理代码 | 查看 Git 状态、差异，执行明确的提交、合并和回退操作 |

## 3. 名词

| 名词 | 定义 |
| --- | --- |
| 项目 | 软件管理的工作集合，含一个主目录，可附加资料目录和仓库 |
| 工作区 | 某次任务实际使用的目录或 Git worktree |
| Agent | Codex 或 DeepSeek 的后台执行环境，不等于模型 |
| 模型 | Agent 使用的模型标识，按账号或服务的可用列表选择 |
| 私聊 | 用户与一个 Agent 的独立会话 |
| 协作群 | 有共享消息记录、成员和任务交接的工作空间 |
| 任务 | 有输入、负责人、状态、验收条件和结果的一项工作 |
| 执行尝试 | 一个任务的某次实际执行；重试产生新的尝试编号 |
| 证据 | 可保存的输入输出、命令结果、代码差异、截图和文件产物 |

## 5. 项目与会话流程

### 5.1 添加和选择项目

1. 用户选择本地目录，软件验证路径存在、可读以及仓库状态。
2. 登记主目录和可选资料目录，不复制项目源码。
3. 显示目录、仓库、分支、未提交修改和 Agent 可用状态。
4. 新建会话时绑定项目与工作区，执行时始终显示其实际位置。
5. 切换左侧项目只切换视图，不改变正在运行的会话目录。
6. 移动或删除目录后，提示重新绑定，保留已有记录。

### 5.2 私聊

项目为可选项。用户可直接从全局私聊入口选择 Agent、模型和权限模式，不得要求先添加项目。关联项目时，再将该项目作为会话工作目录。未关联项目的会话使用应用管理的独立工作目录，不在项目列表中插入虚拟项目。每个私聊有独立厂商会话标识。允许多轮追问；不能把所有私聊拼接为同一上下文。

私聊只对当前用户显示，不自动发送到协作群或其他 Agent。它不是本机多用户加密隔离。两个会话访问同一项目文件时，文件变化仍然可见。

用户可选择特定消息和产物发起交接。界面预览将发送的内容，不默认附带私聊全文。

### 5.3 模型选择

- 模型选项来自当前 Agent 的实际配置和可用目录，显示来源与刷新时间。
- Codex 在支持时额外提供思考强度；DeepSeek 仅显示实际支持的参数。
- 会话记住选定模型；群成员分别配置模型，不使用单一群模型覆盖全部成员。
- 运行中修改模型排到下一轮。当前轮保留原模型并明确显示。
- 厂商支持同会话切换时继续；不支持时提示创建关联会话，不能偷偷重置上下文。
- 模型失效、无权限或余额不足时解释错误，保留输入，不自动换成别的模型。
- 请求模型与实际确认模型分别记录；无法确认实际模型时标注“未确认”。

## 6. 协作群与任务

群聊记录由 AI-gent 保存。各 Agent 拥有自己的执行会话。群消息通过调度器投递，不要求两个 Agent 直接网络互连。

首版提供两种入口：用户 @ 某个成员执行；用户启动固定协作工作流。普通群消息只记录，未被指派的成员不自动执行。

工作流必须显示需求、分工、当前负责人、实际模型、实际工作区、验收条件、交接内容及结果。建议默认最多两轮检查与修改，可由用户调整或继续，防止无限循环。

群内执行产生的任务和消息不能自动伪装为用户指令。其他 Agent 的内容属于协作输入，不能修改用户权限或扩大项目范围。

### 暂停、取消和完成

- 暂停群：停止派发后续步骤；已运行步骤继续，除非用户另行取消。
- 取消执行：向对应运行环境请求中断，并显示确认结果；不能等同回滚已写文件。
- 完成：Agent 回报完成后仍需核对交付和验证结果，进入待验收状态。
- 验收：用户确认完成，或明确授权的自动检查规则通过。
- 重试：展示先前修改和执行状态，创建新尝试，保留旧证据。

## 7. Git 与证据

写入前展示已有未提交修改。首版软件不主动 stash、丢弃或覆盖用户修改。并行写同一工作区应排队；需要并行写时使用不同 worktree。

自动化可以准备代码、验证和差异；提交、合并及回退按用户操作执行。首版没有自动 push、强推、自动发布和自动删除脏 worktree。

证据应包含能实际捕获的数据：消息、请求参数摘要、工具事件、命令退出码、测试输出、差异、commit 标识、附件。截图仅在实际产生或用户上传时保存，不承诺自动记录所有屏幕行为，也不将模型声称“测试通过”视为测试证据。

## 8. 非功能要求

- 数据保存在本机；发送给厂商的任务内容仍受其服务处理。
- 密钥不进入前端状态、普通数据库、诊断导出或日志；遵守实际运行环境的凭证存储边界。
- 文本流可以节流显示，但不能丢失最终消息和关键状态。
- 数据库采用迁移和事务；备份、恢复必须包含对应产物文件。
- 长文本和执行日志按需加载，避免一次载入全部历史。
- 默认不采集遥测。导出前可预览内容，并说明它可能包含项目代码和路径。
- 路径应支持 Windows 中文、空格、盘符与常见长路径错误提示。
- 错误区分认证、模型、协议、权限、网络、进程、Git 和存储故障。

## 9. 典型界面

```text
项目列表         会话/群聊                   任务与证据
网站 A           Agent / 模型 / 工作区      当前步骤
  Codex 私聊     消息与执行事件             Git 差异
  DeepSeek 私聊  审批或问题                 测试输出
  协作群         输入框、@、发送、取消      交付文件
网站 B
```

界面需覆盖空项目、缺运行环境、未登录、模型加载失败、执行中、等待审批、失败、取消、冲突、目录失效和磁盘写入失败。

## 10. 第一版边界

不复刻原厂全部客户端功能，不导入其全部历史，不读取不可获得的内部推理。首版不保证操作系统级目录隔离；工作目录和 Git worktree 本身不是安全沙箱。
